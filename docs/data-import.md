# 纸质记录与历史相册导入方法

这是一次可审计的导入工作流，不是无需检查就能自动覆盖所有家庭数据的工具。仓库公开领域模型、归一化、媒体去重与删除逻辑；具体家庭的原图、转录清单和一次性迁移脚本保留在私有工作目录。

## 纸质本子逐页处理

1. 先导出 APP 当前 JSON、媒体目录并保留原始照片。为本次导入建立私有 manifest，记录原文件名、拍摄时间、页序号、文件散列及目标日期。
2. 逐张读取图片，转录为页级中间数据。不要只用缩略图判断手写数字。保留每一行的原文、时间原文、字段和疑点。
3. 日期缺失时，先确认是否每日一页、有无跳天，再依据相邻页推断。无法确认的日期和数字进入待核对，不能依序猜数。
4. 向记账者确认符号口径。此案例确认：单个奶量是实际喝下；两个奶量分别为冲泡和实际；多个 √ 是多次小便，○ 是换尿布。其他本子不能自动沿用这套规则。
5. 分开保存 preparedMl 与 value。只有二者明确时才计算剩余；剩余不等于已经丢弃。用户后续确认某批未知剩余就是零，可以对指定历史记录作版本化补全，并保留确认依据。不要改变未来未知值的默认语义。
6. 亲喂分钟与瓶喂母乳毫升分开；补剂仅有勾选时不猜剂量；缺时间使用 `timePrecision: day`，不伪造精确时分。
7. 为页和行生成稳定 ID，如 `notebook-DATE-row-KIND`。重跑同一源文件应更新同一条，不新增重复记录。与旧 APP 记录匹配时检查时间、类型、值和来源，含糊匹配人工核对。
8. 使用领域 `validateRecord`、`normalizeDrafts`、`mergeRecords` 及版本控制合并。更新携带 targetRecordId/baseVersion，手机原条目已经变更时进入待核对，不强制覆盖。
9. 每页保留原图作为 source 附件；护理记录引用来源。按日汇总逐项核对奶量、亲喂时长、小便、换尿布与补剂，最后再整体导入。

合成的单行示例：

```json
{"id":"notebook-example-row-1","kind":"bottle","at":"2026-01-20T15:00:00+08:00","value":70,"unit":"ml","details":{"preparedMl":"80"},"note":"纸质记录：冲80、喝70","sourceText":"15:00 80ml 70ml"}
```

## 照片、视频与 Live Photo

- 先列出手机相册资源及元数据，再制作联络表筛选宝宝相关内容；仅凭创建日期不能认定照片属于宝宝。
- 保留 asset ID、原拍摄时间、文件内容散列及来源。已有相同资源合并，不按文件名相同就覆盖。
- Live Photo 的静态照片和伴随视频作为一组保留；视频不当作另一次成长事件重复计算。
- 私有导入清单区分入选、排除、待审和已采集；逐项验证文件存在、非零、媒体可播放。
- APP 相册只显示 memory 媒体，纸质本 source 原页另作追溯。导入后抽查各月份、视频和 Live Photo。

## 删除与校正

APP 删除移除该媒体引用，并在无人再引用时清理本地文件；Live Photo 伴随视频一起处理。护理记录不因删除照片而丢失，手机系统相册原件不由此功能删除。删除与清理失败需要重试，不能仅删缩略图后留下失效引用。

验收时用临时样例测试删除，真实家庭资料保持备份。导入报告应列出覆盖数、保留数、相册主项目数、Live Photo 伴随文件数，以及未解决的原文；这些数字不可混为一个“照片数量”。
