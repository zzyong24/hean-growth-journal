# 小聆护理语音路由

## 当前链路

实体麦克风 → 官方 ASR → `agent/` → 禾安兼容模型入口 `/api/voice/chat/completions` → 禾安记录/查询服务 → 官方语音播报。

Lua 看板单独读取 `/api/display/summary`，不承担护理写入。禾安服务只分类最新一条用户输入，不会因之前的查询、失败或音乐请求重做历史动作。护理工具在服务内部执行，所以屏幕是否运行小应用不会影响工具可见性。

聆思平台应用的模型地址设为禾安服务的 `/api/voice/chat/completions`，模型名为 `hean-care`，使用通过 `/api/voice/pair` 签发、限定账号及宝宝的语音令牌。令牌只通过私密配置传递，不能放入代码或看板。部署并启用 `agent/`，保留官方 ASR、播报、打断和设备生命周期。

## 记录和回执

- 喝奶、亲喂、尿布、睡眠、测量、吸奶、辅食、用药、补剂、观察及纠正，保留原话交给 `hean_record`。省略主语的“刚喝了100毫升”也是护理记录。
- 原话先持久化，再异步解析；服务断开或客户端超时不丢弃已接收的任务。同一轮重试复用请求编号，新一轮不会复用已保存事件。
- 只有 `saved` 回执表示已写入云端；手机确认后才表示手机已同步。`processing` 表示处理中，`review/failed` 不得说成功。没有回执时查 `hean_receipt`，不盲目重录。
- 冲泡量和实际量分别保存；不把“刚冲了120毫升”直接算作摄入。开始、结束和撤销喂养沿用 APP 的记录逻辑。
- 查询使用当前云端合并状态，不读取聊天中的旧数字。未记录不代表没有发生。

音乐意图只取禾安家庭曲库的临时链接，Agent 只接受三个固定曲目 ID。通过官方音频 URL 通道播放，避免受小应用模式限制的专用音乐 MCP。唤醒/新语音会打断播放，不承诺自动续播。

## 原生操作

拍照、识别眼前物品、音量/亮度、设备状态、天气、提醒等使用独立 `native` 分类，从本轮工具目录选择能力，并强制返回对应工具调用。不能只说“好的”当作执行。参数沿用平台提供的 schema；不添加不存在的工具或改写固件工具名。

调用由官方 Agent 执行，摄像头生命周期保持原样。带回执行结果的后续模型请求只做结果反馈，避免同一句触发二次拍照。功能说明、假设、否定命令不应执行；未知工具或失败结果不能宣称完成。

## 冲突原因与验证

原来只调整 Main Prompt，仍有两层限制：托管 Agent 在小应用运行时缩减工具目录，固件也拒绝部分设备 MCP。前者会把护理记录误送给 `code_agent_bridge`；后者使音乐仅口头回应，设备没有取流。

当前使用独立护理入口和支持小应用共存的音频通道。验证需同时观察实体看板、设备音频日志、服务回执和记录数量。CLI 查询成功不能单独证明实体麦克风/扬声器链路；用户听到音乐也不能单独证明记录保存成功。

另一个已修复回归是：目录中有拍照工具，但 `other + auto` 路由只口头回应，没有执行。判断时先区分“没有工具”“没有发出调用”“设备拒绝”“实际成功但没播报”，不能一概归为小应用限制。

当前固件在看板模式下仍会拒绝拍照；退出看板时拍照成功，不能算两者共存已解决。v0.1.6 修正这一拒绝被平台误标成功并静默结束的情况，明确反馈失败，保留看板。完整共存需要后续固件适配。
